# Agent Note: 基于 SkillHub 的技能中心

Status: proposed

[English](2026-08-24-skillhub-backed-skill-center.md) | 中文

## 问题

dsh 已经可以发现本地和随包 skill，通过 `skill.list` 暴露用户可调用目录，从 composer 插入 `/name` 引用，并通过现有 skill 注册表加载选中的 skill。但它还没有用于发现远程 skill、检查内容、安装或停用，以及管理用户已安装集合的产品界面。

所需体验是 2026-08-24 提供的六张参考截图所展示的 Gangtise Skills 面板：社区目录和个人目录、卡片式发现、搜索和分类筛选、双模式详情弹窗、安装状态、启用控制、本地下载，以及从已安装 skill 直接进入对话的路径。

只复制视觉会让重要生命周期没有定义。远程目录条目不是可调用的 dsh skill，安装过程不能暴露只写入一部分的内容，停用必须同时影响模型调用和用户调用，而项目本地的同名 skill 可能覆盖已安装 skill。产品需要一项明确约定，将 marketplace、托管包存储、现有 skill 注册表和 Web 客户端连接起来。

## 提案

增加原生 dsh **技能中心**，后端使用独立部署的 [SkillHub](https://github.com/iflytek/skillhub) 实例。SkillHub 拥有远程目录、搜索、包版本、发布者身份、下载产物和发布工作流。dsh 拥有 Web 体验、安装记录、包校验、启用状态、工作区解析和调用。

SkillHub 始终是社区内容的真源：维护者在 SkillHub 中创建和更新社区 skill，dsh 通过其分发 API 获取元数据和带版本的产物。dsh 不复制发布者记录、不编辑社区版本，也不维护另一套独立社区索引。

通过 Host 侧适配器集成 SkillHub，不嵌入或修改它的前端。社区条目不会进入 `ctx.skills`；只有安装到 dsh 托管 skill 存储中且已启用的包才会贡献给现有注册表。这样可以保留当前的 [skill 注册表和调用行为](../../../../docs/subsystems/skills.md)，包括工作区相关优先级和 `/name` 用户手势。

第一阶段只连接一个已配置的 SkillHub 注册中心实例，并交付完整公开路径：社区发现、详情、精确版本安装、启用、停用、更新、卸载、下载和在对话中使用。它不要求 SkillHub 认证，也不公开私有 namespace。但远程身份仍由 dsh 配置的 `registryInstanceId` 与 namespace、slug 和 version 组成，从而避免以后增加多注册中心功能时迁移安装记录。

产品负责人已于 2026-08-25 确认这份修订后的一期范围为实施基线。在功能交付并通过验证前，本说明仍保持 `proposed` 状态。

技能中心内容区和详情弹窗逐像素复现所提供的 Gangtise 截图，包括尺寸、间距、字体、颜色、边框、阴影、卡片密度、控件位置和交互状态。该要求与普通 dsh 组件样式不一致时，以本要求为准。周围的 dsh 应用外壳仍归 dsh 所有；Gangtise 产品 Logo、金融导航、行情栏和无关全局控件不属于复制范围。

## 目标和范围

完整目标包括以下结果：

- 浏览、搜索、筛选、分页和刷新远程社区目录；
- 在安装前检查身份、发布者、版本、使用指标、输入示例、安装命令和渲染后的 `SKILL.md`；
- 无需重启 dsh 即可安装、更新、启用、停用、卸载和下载 skill；
- 浏览当前 dsh 安装可见的全部个人 skill，并区分托管安装与项目、用户、自定义、随包和运行时来源；
- 通过现有 `/name` 路径把已启用且允许用户调用的 skill 插入对话；
- 在所配置服务器和用户身份允许发布时，创建 skill 并上传到 SkillHub；以及
- SkillHub 不可用时保留可用的最近数据和明确的恢复操作。

第一版不包含认证、私有 namespace、创建、上传、发布、SkillHub 管理、审核队列、组织和计费管理、注册中心联邦、后台自动更新、详情弹窗内执行 skill、评分、评论、推荐或分析仪表板。

## 信息架构

技能中心是 dsh 主导航可进入的一级 Web 路由。该路由有两个稳定的顶层标签页：

| 标签页 | 用途 | 默认状态 |
|---|---|---|
| 社区 Skills | 发现所配置 SkillHub 的目录 | 全部分类，按相关性排序 |
| 我的 Skills | 管理当前 dsh 安装可见的 skill | 全部来源 |

标签页选择、搜索文本、分类、个人筛选、排序和滚动位置属于视图状态。它们可以在当前浏览器的路由切换间保留，但不会进入会话日志或模型上下文。

### 社区 Skills

页头包含标题、简短副标题和搜索输入框。分类行以 `全部` 开始，随后把 SkillHub label 渲染为分类；注册中心没有返回 label 时只显示 `全部`，dsh 不虚构特定领域分类。窄屏时分类行可以横向滚动。搜索采用防抖并由服务器执行，同时与所选分类组合。改变搜索或分类会重置分页。

目录使用响应式网格：在参考截图的宽桌面尺寸显示三列，中等宽度显示两列，窄屏显示一列。每张卡片高度稳定，并展示：

- 展示标题；只有最新版本具有可信 `publishedAt` 且距 Host 时钟不超过七天时才显示 `NEW` 标记；
- 截断后的描述，并提供可访问的完整文本标签；
- 显示发布者、语义版本、Star 数和下载量，保留参考设计中的两个指标位置，但不虚构 SkillHub 未提供的浏览量；以及
- 当本地存在完全相同的 marketplace skill 身份时显示已安装标记，不受已安装版本是否启用影响。

选择任意非控制区域会打开详情弹窗。已安装状态不能从卡片计数或标题推断，而是来自 Host 安装服务，并通过不可变的 marketplace skill 身份关联。

网格需要定义骨架加载、搜索无结果、分类为空、首次加载失败、陈旧缓存结果、下一页加载和下一页失败状态。陈旧缓存结果仍可浏览，并显示重试操作。请求待处理期间，分页不能重新排序已经渲染的卡片。

### 我的 Skills

页头包含标题、副标题、搜索输入框和 `上传 Skill` 命令。筛选行包含 `全部`、`我安装的`、`我创建的` 和 `我上传的`。后两项需要经过认证的 SkillHub 身份；身份不可用时，其空状态会说明要求并提供所配置的登录操作，而不是让整个页面失败。

`全部` 和 `我创建的` 中的第一张卡片是 `去创建我的专属 Skills`。它会启动下文定义的发布编辑器。其他卡片沿用社区卡片的信息密度，并增加来源、解析状态、启用状态和更多操作菜单。

托管安装提供启用开关，以及查看详情、有更新时更新、下载和卸载操作。已发现但不受托管的本地 skill 会显示其来源和解析后的路径；dsh 不通过 marketplace 菜单删除、覆盖或发布该 skill。随包和运行时 skill 只读。当其他来源在所选工作区中赢得同名项时，卡片会指出当前生效的来源，而不会把托管安装呈现成已解析的 skill。

搜索针对最近一次权威个人目录在本地执行，并匹配展示标题、skill 名称、描述和发布者。个人筛选可以与搜索组合。注册表失效或安装完成后会刷新目录，无需重新加载路由。

## Skill 详情弹窗

详情弹窗可以从任一目录打开，桌面宽度匹配所提供的详情参考 crop，窄屏使用全高抽屉，具备焦点约束、Escape 处理、焦点恢复，并且不嵌套另一个弹窗。页头展示标题、规范 kebab-case 名称、发布者、版本、Star 数和下载量。

双选项分段控件在 `在 dsh 中使用` 与 `本地 / 第三方安装` 之间切换正文。切换模式不会关闭弹窗或丢弃已加载的详情数据。

### 在 dsh 中使用

安装前，该模式只在版本明确提供 `metadata.examplePrompt` 时显示可复制的输入示例；该字段缺失时整个示例区块不显示。随后显示完整 `SKILL.md` 的安全 Markdown 预览。页脚提供 `安装到我的 Skills` 和 `取消`。

安装期间，主操作报告离散 Host 阶段 `正在下载`、`正在校验` 或 `正在提交`，并在阶段内显示不定进度；它不会虚构字节百分比。重复点击会被忽略，并且只有文件系统变更已经开始后，关闭弹窗才需要确认。成功后，同一弹窗会原地切换到已安装状态。

安装后，页脚提供 `卸载`、`在对话中使用` 和 `取消`。已停用的 skill 改为提供 `启用并在对话中使用`。安装始终固定当前展示的确切版本。存在较新版本时会增加标明目标版本的更新操作，并要求用户明确确认；dsh 不进行自动或后台更新，而且在替换成功提交前不会删除当前已安装版本。

`在对话中使用` 永远不会从弹窗执行 skill，也不会提交提示词。它会返回最近活跃的普通会话；没有普通会话时创建一个空白普通会话；通过现有输入触发行为在已保存的 composer 光标位置插入以空白分隔的 `/name ` token，并聚焦 composer。插入位置前后的现有草稿文本和选区会被保留。用户提交后，Host 仍是解析和注入 skill 的权威来源。

如果 skill 不允许用户调用，弹窗不会显示 `在对话中使用`；它会说明该 skill 只能由模型选择。如果其他来源当前赢得同名项，该操作会指出生效来源，并且不会暗示本托管包将被执行。

### 本地 / 第三方安装

该模式显示由 dsh 根据适配器数据格式化的官方 CLI 命令 `skillhub install <slug> --namespace <namespace> --version <version>`，随后显示同一份 `SKILL.md` 预览。SkillHub 本身不提供安装命令字段。该命令不会替用户添加 `--force`、agent 或目标 scope。页脚提供 `下载到本地` 和 `取消`；当 skill 同时已安装到 dsh 时，还会在页脚另一侧提供 `卸载`，与所提供参考行为一致。

`下载到本地` 通过 Host 端点下载当前显示的确切版本，该端点会保留认证并在流式传输前校验上游产物。此操作不会改变 dsh 安装状态。文件名包含规范名称和版本。

## 创建和上传

`去创建我的专属 Skills` 会打开 dsh 原生编辑器，用于编辑展示标题、规范名称、描述、分类、输入示例、调用策略和 `SKILL.md`，并可添加资源文件。编辑器采用与安装相同的包规则进行校验，并且可以保存本地草稿而不发布。

`上传 Skill` 接受目录 bundle 或受支持的压缩包，在本地完成校验，展示解析后的元数据和文件清单，并在上传前要求明确确认。发布需要经过认证的 SkillHub 身份和服务器报告的权限。版本冲突、策略检查拒绝和服务器校验错误会保留在相关字段或文件上。

发布绝不是本地创建或安装的隐式副作用。上传成功会刷新 `我上传的`；发布成功只在服务器报告该版本公开可见时刷新 `我创建的` 和社区目录。

创建和上传是第二阶段交付内容，因为截图确定了入口，但没有确定完整编辑器或服务器策略。第一阶段只有在入口可以进入明确标记的不可用状态时才会显示入口；不能呈现无响应按钮。

## 领域模型

Marketplace 目录与可调用 skill 目录是两个独立模型：

| 模型 | 所有者 | 含义 |
|---|---|---|
| MarketplaceSkill | SkillHub 适配器 | 一个远程产品身份，包含最新版本概述和发现元数据 |
| MarketplaceSkillVersion | SkillHub 适配器 | 一个不可变版本，包含预览、产物定位、完整性数据和安装提示 |
| SkillInstallation | dsh Host | 一个本地已安装的 marketplace 身份，包含固定版本、启用状态、记录和更新状态 |
| SkillSummary / SkillDefinition | 现有 `ctx.skills` 注册表 | 经过提供方优先级处理后，当前可发现和加载的一个 skill |
| PersonalSkillRow | dsh Host 投影 | 安装、本地发现来源、所有权和当前工作区解析结果的联合管理行 |

远程身份不是展示标题或 kebab-case 调用名称。安装和更新操作使用不可变 SkillHub 身份和版本；调用继续使用 `SKILL.md` 中经过校验的 skill 名称。包名称与目录元数据不一致的版本会被拒绝。

安装相同注册中心身份和确切版本是幂等操作。当同名托管安装已经存在时，来自不同社区身份但规范 skill 名称相同的安装会被拒绝，并指出已安装来源。项目、自编、随包或运行时同名 skill 不阻止安装，因为现有提供方优先级继续作为权威规则；UI 必须显示当前实际解析到的来源。

安装状态机为 `absent -> downloading -> validating -> committing -> installed-enabled`，并包含 `installed-disabled`、`updating`、`uninstalling` 和 `failed` 操作状态。只有两个 installed 状态是持久状态。进程重启会丢弃瞬态进度，并从记录和包目录重建持久状态。

## SkillHub 适配器

Host 定义提供方无关的 marketplace 服务和 SkillHub 适配器。配置包括 `registryInstanceId`、基础 URL、可选公开 Web URL、凭据引用、请求超时、缓存时长、分页大小上限、产物限制和发布启用状态。目录缓存默认 5 分钟内为新鲜数据，并可在明确标记陈旧的情况下继续浏览最多 24 小时；部署方可以覆盖这两个时限。密钥保留在 Host 凭据服务中，永远不会返回浏览器。

适配器把 SkillHub 响应规范化为 dsh 自有类型，并拥有端点路径、认证请求头、分页 token、分类词汇、指标可用性、产物 URL 和上游错误转换。Web 客户端永远不会直接调用 SkillHub，也不会依赖 SkillHub 响应字段。

服务器允许时，只读发现可以匿名运行。经过认证的操作会以带类型的 `authentication-required` 或 `permission-denied` 结果失败。限流会保留最近一次成功页面，采用有界的 dsh 本地指数退避，并提供手动重试；上游缺少 `Retry-After` 时，适配器不会虚构重试时间。不支持的可选元数据会被省略，而不是伪造。

第一阶段要求适配器支持目录列表、详情、版本产物下载和安装提示。部署的 SkillHub 容器按镜像 digest 固定，契约测试针对实际固定版本的 OpenAPI 运行，而不依赖其自报版本字符串。schema 不兼容时，社区 Skills 会以带类型的配置错误变为不可用，但我的 Skills 和已安装 skill 调用继续工作。第二阶段增加身份、所有权查询、上传、创建和发布。适配器约定允许替换成其他注册中心实现，而无需改变 Web 包或安装服务。

## 安装和注册表行为

Marketplace 包保存在 dsh 托管存储中，该存储位于普通 `.dsh/skills` 和 `.agents/skills` 根目录之外。托管 skill 提供方只把已启用且完整提交的包贡献给 `ctx.skills`。因此，未安装的社区条目和已停用安装不会出现在面向模型或面向用户的目录中。

安装会下载到唯一 staging 目录，校验传输状态，执行所配置的压缩及解压大小限制，拒绝绝对路径、父目录穿越、设备文件、不安全链接、重复路径、过多文件和不支持的包根目录，然后对照 SkillHub 的逐文件 SHA-256 清单检查每个解压文件，并重新计算 `resolve` 返回的按路径排序 fingerprint。它还会独立采用与文件系统提供方相同的规则解析 `SKILL.md`，并校验包身份与目录元数据一致。提交会先原子写入包和安装记录，再触发 `skills/change` 失效。失败会删除 staging 数据，并保留之前已安装的版本不变。

安装记录包含 `registryInstanceId`、不可变 marketplace 身份、适配器名称、来源服务器、规范 skill 名称、确切版本、已校验的逐文件哈希清单、重新计算的 fingerprint、安装时间、启用状态和包位置。它不会声称存在 SkillHub 并未提供的 ZIP 摘要。提交后包目录不可变。更新会暂存完整替换项，并原子切换安装记录，因此回滚会保留之前的版本。

停用会改变安装记录并使托管提供方失效，但不会删除包文件。卸载会先移除提供方贡献，再删除安装记录和托管包。卸载失败会报告 skill 已不可用还是仍处于活动状态；UI 不能从失败请求自行猜测。

更新会保留之前的不可变包和安装记录，直到替换提交已经持久化。卸载使用可恢复 tombstone，使重启对账可以完成删除或恢复最后一个真实活动状态。启动时，安装服务会清理遗留 staging 目录，对账安装记录、包目录和 tombstone，并只在确定持久状态后发送失效事件。恢复过程永远不会提升未经校验的包。

现有优先级继续作为权威规则。项目 skill 可以覆盖托管安装；按 scope 划分的运行时或 preset 提供方可能在不同会话中解析出不同结果。安装、启用或更新成功表示托管包可供注册表使用，不表示它会赢得每个工作区查找。

## Host API 和事件

扩展带类型的 ApiProxy skill 领域，提供与以下分组等价的操作：

- `skill.marketplace.list`、`skill.marketplace.get` 和 `skill.marketplace.download` 用于远程发现；
- `skill.installation.list`、`skill.installation.install`、`skill.installation.update`、`skill.installation.setEnabled` 和 `skill.installation.uninstall` 用于本地管理；
- `skill.publish.identity`、`skill.publish.validate`、`skill.publish.upload` 和 `skill.publish.release` 用于第二阶段发布；以及
- 现有 `skill.list` 用于按会话解析且允许用户调用的 composer 目录。

每个变更请求都携带调用方生成的幂等键。结果标识所请求的 marketplace 身份、版本、最终持久状态和带类型的失败原因。浏览器取消会尽可能停止网络工作，但 Host 越过原子提交点后，不会声称提交已经回滚。

Host 转发粗粒度 marketplace 缓存和安装变更失效。客户端重新拉取当前查询或个人目录，而不是应用服务器 diff。现有 `skills/change` 仍然是 `ui-skill` 等可调用目录消费方唯一使用的失效信号。

## Web 客户端所有权

使用现有 slot 系统，把该路由实现为新的客户端插件包。该包拥有路由视图状态、弹窗状态、查询协调和呈现。Host 服务拥有远程数据、安装变更、校验和工作区解析。业务组件接收 JSON 兼容数据和回调；不会接收 Cordis 上下文或调用 SkillHub。

该包保留外围 dsh 外壳，并复用其路由组合、图标库、locale 服务和焦点行为。Skill 中心内容区和详情弹窗内部拥有一小组按照所提供 Gangtise 桌面截图校准的字面视觉 token，避免 dsh 主题变化移动像素基线。它不会增加组件库、Tailwind、Gangtise 品牌、金融导航、行情条、无关全局控件或第二套全局外壳。产品文案使用中文，并提供英文 locale 对侧内容。移动端是响应式推导，不作为第二套像素参考。

Markdown 预览使用现有安全渲染器，禁用原始 HTML 和可执行嵌入。代码和不可断开的长文本在有界预览区内滚动，而不会撑宽弹窗。复制按钮提供可访问名称和短暂成功状态，并且不会改变布局。

## 加载、失败和并发

列表和详情读取使用可取消、按查询 key 划分的 single flight，以及有界的最近成功缓存。较晚完成的旧查询不能覆盖较新的查询。陈旧目录数据会显示最近成功时间和手动重试操作；超过默认 24 小时陈旧上限后，会替换为带类型的不可用状态。安装状态来自 Host 响应和失效事件，而不是卡片的乐观切换。

同一个 marketplace 身份一次只运行一项变更。该身份正在变更时，安装、更新、启用、停用和卸载控件都会禁用，但其他卡片仍可使用。使用相同幂等键的重复请求返回原始结果；使用不同 key 的并发请求会收到 `operation-in-progress`。

离线或 SkillHub 不可用不会破坏 `我的 Skills`、当前 skill 调用或本地来源发现。社区缓存数据会明确标记为陈旧。不需要上游数据的托管安装操作仍然可用，包括停用和卸载。

## 安全和信任

Skill 包只有在明确安装后才成为受信任指令；浏览和预览永远不会让其内容对模型可见或可执行。详情预览不会解析远程图片或执行包脚本。安装 skill 不会运行设置命令。

产物获取遵循所配置的凭据请求重定向策略，根据 Host 配置强制执行 TLS，并记录来源、身份、版本和已校验 fingerprint，而不记录凭据。发布会在发送前校验文件名和内容，并且永远不会上传所选包根目录之外的文件。

安装确认会显示发布者、来源服务器、版本、调用策略，以及是否存在可执行资源文件。SkillHub 当前既不提供包签名，也不提供 ZIP 摘要，因此第一阶段不宣称真实性保证：它会校验每个已公布文件的 SHA-256 和重新计算的 `resolve.fingerprint`。未来可以通过注册中心签名策略增强准入。

## 交付阶段

一期按以下七个有顺序、可独立评审的工作包交付。任何工作包都不能在对应 Host 行为和失败状态完成前暴露其控件。

1. **固定契约和 fixture。** 固定已部署 SkillHub 的镜像 digest；从实际目录列表、详情、版本、文件、resolve 和下载响应生成契约 fixture；把所提供六张图片 crop 纳入测试 fixture；固定浏览器、字体、时钟、label、指标和目录数据以保证确定性比较。退出关卡：SkillHub 契约套件和空视觉测试壳无需网络即可运行。
2. **增加 marketplace 模块。** 增加 Host 侧 skill marketplace 模块，以小型 dsh 自有接口提供目录列表、详情、精确版本解析和产物获取。SkillHub 路径、分页、label、字段转换、匿名限流、缓存行为和 OpenAPI 兼容性全部保留在 SkillHub 适配器内部。退出关卡：规范化、陈旧缓存、取消、429、畸形响应和不兼容契约测试均通过调用方使用的同一接口。
3. **增加托管安装和注册表贡献。** 增加本地托管 skill 模块，由它拥有 staging、压缩包准入、逐文件哈希、fingerprint 重算、安装记录、不可变包目录、tombstone、启动对账、幂等性，以及一个只贡献已启用且完整提交包的 `ctx.skills` 提供方。退出关卡：安装、冲突、更新回滚、启停、卸载、崩溃点恢复、优先级和 `skills/change` 测试无需 ApiProxy 或 Web 代码即可通过。
4. **暴露 Host 传输。** 扩展 `packages/host/apiproxy/src/api/skills.ts`、对应 schema 和 fetch dispatch，加入 dsh 自有的 marketplace 与安装操作；增加经过认证的 Host 下载面和粗粒度缓存／安装失效事件。wire 永远不暴露 SkillHub 响应类型、凭据或包路径。退出关卡：契约、dispatch、取消、幂等、下载和事件测试使用 fake marketplace 与安装实现通过。
5. **构建只读 Skill 中心界面。** 增加专用 `@deepseek-ai/dsh-client-ui-skill-center` 包，并在 `packages/bundle/web-app/cordis.patch.yml` 中挂载。先完成导航、社区 Skills、全来源我的 Skills 投影、搜索、label、分页、陈旧／错误状态和双模式详情弹窗，再启用变更控件。退出关卡：六张参考 crop 全部满足像素阈值，并通过键盘、焦点、长内容、locale 和响应式组件测试。
6. **连接生命周期操作和对话交接。** 接入精确版本安装、更新确认、启停、卸载、本地下载、变更进度和恢复 UI。通过狭窄的可编程 composer 接口复用现有 `ui-input-trigger` `/name` 插入路径；不增加第二条调用 wire。退出关卡：组件和组装测试覆盖每个持久状态、重复操作、来源冲突、草稿／选区保留和用户调用策略。
7. **证明组装版本。** 使用确定性 fixture 运行从浏览到卸载的无密钥 Web 流程，并针对固定的本地 SkillHub 单独运行 smoke；在更新／卸载每个转换点执行重启；验证故障隔离、压缩包限制、无障碍、两个 locale 和生产 bundle 组合；最后把本 Agent Note 从拟议行为更新为实际交付事实。

二期是独立的提案级增量：SkillHub 身份、我创建的和我上传的查询、本地编辑器、包上传、发布校验和版本发布工作流不进入以上七个工作包。

每个阶段都不能留下无响应的可见控件。后续阶段控件要么不显示，要么进入明确的能力要求状态。

## 考虑过的替代方案

**在 dsh 中嵌入 SkillHub 前端。**不予采用，因为它会重复导航和认证，绕过 dsh 的主题与 slot 组合，暴露上游路由假设，同时仍需要另一套桥接来完成本地安装和会话相关调用。

**Fork 并重新设计 SkillHub 前端。**不予采用，因为 dsh 会继承无关的前端发布生命周期，而本地包存储、提供方优先级和 composer 行为仍属于 dsh。适配器可以把上游 API 变更限制在一个 Host 包内。

**把所有远程 SkillHub 条目直接注册到 `ctx.skills`。**不予采用，因为仅仅浏览社区目录就会让尚未安装的第三方指令对模型和 `/name` 用户可见。Marketplace 是发现数据；安装才是明确的信任和可用性转换。

**直接安装到 `~/.dsh/skills`。**Marketplace 托管包不采用这种方式，因为普通文件系统条目没有持久来源、固定版本、摘要、停用状态或原子更新记录。现有用户自编 skill 继续在那里受支持，并作为不受托管的个人条目出现。

**为 marketplace 包重新实现 skill 运行时。**不予采用，因为当前注册表、提供方优先级、调用策略、`skills/change`、`skill.list`、`/name` 手势和 `skill` 工具已经拥有运行时行为。新增工作只增加管理层和一个提供方。

## 验收标准

- 使用固定 Chromium 和字体文件的确定性 Playwright 组件 fixture，以 `maxDiffPixelRatio <= 0.002` 复现所提供的两张 `1077 x 638` 目录 crop、三张 `802 x 638` 详情 crop 和一张 `807 x 638` 详情 crop。比较覆盖信息层级、间距、字体、颜色、搜索、label 分类、卡片网格、指标、已安装标记、分页和已观察到的弹窗状态。动态时间戳和计数器由 fixture 控制，而不是遮罩。这些尺寸是内容 crop，并不声称是浏览器视口；外围 dsh 外壳不参与比较。另用组装测试验证加载、空、失败、陈旧、重试和可用的移动响应式状态，不把它们当作已有像素参考。
- 详情弹窗复现两个展示模式和观察到的四种生命周期组合：未安装的 dsh 使用、未安装的本地下载、已安装的 dsh 使用、已安装的本地下载。复制、预览、安装、卸载、下载、取消和进入对话操作具备键盘和屏幕阅读器行为。
- 安装有效 SkillHub 包后，无需重启 dsh 即可通过现有注册表和 composer 目录看到它。停用会将其同时从模型调用和用户调用中移除但保留文件；启用会恢复；卸载会移除其托管贡献和安装记录。
- 中断、无效、过大、包含路径穿越、完整性不匹配和冲突的安装永远不会暴露部分包，也不会破坏之前已安装的版本。重试的变更操作具有幂等性。覆盖更新和卸载每个状态转换点的重启测试要证明，对账会返回唯一真实的持久状态，并且不会提升未经校验的内容。
- 我的 Skills 会联合托管和非托管来源，分别报告启用状态和解析状态，在失效后刷新，并正确说明项目或按 scope 划分的同名覆盖。
- `在对话中使用` 会保留现有草稿，通过既有输入路径插入以空白分隔的 `/name `，聚焦 composer，并且在用户发送提示词前不会提交或调用任何内容。
- SkillHub 故障时，已安装 skill、本地发现、我的 Skills、停用、卸载和调用仍然可用。社区发现会显示带类型的失败，或明确标记的陈旧缓存数据。
- 浏览器永远不会收到 SkillHub 凭据或产物文件系统路径，不会直接调用 SkillHub，并且在明确安装和调用前，永远不会执行预览包内容或使其对模型可见。
- 组件测试覆盖卡片、筛选、弹窗焦点、复制状态、窄屏布局、长名称、长描述、安装转换、来源冲突和两种 locale。Host 测试覆盖适配器规范化、压缩包校验、原子提交、回滚、安装记录、提供方失效、优先级、幂等性和取消。
- 无密钥的组装 Web 测试覆盖浏览 -> 详情 -> 安装 -> 在对话中使用 -> 停用 -> 启用 -> 卸载；回放 fixture 证明 marketplace 元数据或已安装文件以后变化时，现有对话仍保持稳定。
- 第二阶段验收还要覆盖经过认证的创建、上传校验、权限失败、版本冲突、发布确认，以及我创建的和我上传的刷新，并且本地保存不能产生发布副作用。

## 风险

SkillHub 的公开 API 和包元数据无法提供参考截图中的每个字段。适配器把 label 映射为分类，把 Star 数映射到参考设计的第一个指标位置，只从 `metadata.examplePrompt` 显示示例，并省略其他不可用的可选数据而不是伪造。在确定第一阶段估算前，必须用契约测试覆盖固定部署版本的实际 OpenAPI 约定。

远程包具有广义上的可执行性，因为它们的指令在调用后可以引导工具。压缩包校验可以防止安装期间的文件系统攻击，但无法建立发布者信任或指令安全性。部署所有者需要来源 allowlist、摘要策略和清晰的安装确认。

同一个 skill 名称在不同工作区和 agent preset 中可能解析出不同结果。因此，全局我的 Skills 页面可以全局报告安装和启用状态，但解析状态必须始终指出所选会话或工作区上下文。

创建和上传依赖认证、授权、审核和版本策略，这些内容无法从所提供截图中看到。在部署的 SkillHub 约定得到验证前，这些工作流保留在第二阶段。

大型目录和大型 `SKILL.md` 文件可能让网格与预览成本过高。Host 和客户端需要有界分页、产物限制、卡片内容截断、详情延迟加载和有界预览渲染。
